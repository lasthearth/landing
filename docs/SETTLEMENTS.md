# Поселения: частые ловушки

> **Что это.** Контракт домена поселений и правила гейтинга. Код — `entities/settlement/`, `features/settlements/`.

## Данные

- `GET .../roles` и `GET .../members` **не существуют**: роли и состав приходят внутри `Settlement`.
- Мутации возвращают `{ settlement }` → перерисовывайте из ответа мутации, без дозапроса.
- `Settlement.leader` — `@deprecated`. Владельцы — члены, у которых `role_ids` содержит `'owner'` (`OWNER_ROLE_ID`).
- `members` **уже включают владельцев**: никаких `members.length + 1`.
- Обязательные поля тела в мутациях ролей/владения/контактов — без них `INVALID_ARGUMENT`.
- Чтение `attachments[0].url` — только с optional chaining (вложения бывают пустыми).

## Безопасность

- `role.name` и `contact_info` выводить **только интерполяцией `{{ }}`** — сервер не экранирует (XSS).
- Клиентская валидация: имя роли 1–64, контакты ≤512, запрет символов `<` и `>`.

## «Гильдия» — фронтовый костыль

- Маркер `[GUILD]` в `name`, режется хелперами `entities/settlement/lib/` (`is-guild-*`, `get-settlement-display-name`, пайп `settlement-display-name`).
- На бэк уходит `type: 'CAMP'`; шкала уровней и кнопка повышения гильдии не показываются.
- Так задумано (см. `docs/history.md` §3.1): не «исправляйте», не убирайте маркер, пока бэкенд не получит тип.

## Гейтинг кнопок

| Действие                                    | Условие                                   |
| ------------------------------------------- | ----------------------------------------- |
| Инвайты                                     | `owner ∨ PERMISSION_INVITE_MEMBER`        |
| Заявки                                      | `owner ∨ PERMISSION_REVIEW_JOIN_REQUEST`  |
| Роли, контакты, владение, картинка, уровень | только `isOwner`                          |
| Кик                                         | `isOwner ∨ admin`                         |
| Выход                                       | не-owner (или owner при втором владельце) |

Чистые функции гейтинга покрыты тестами (`entities/settlement/lib/*.spec.ts`) — менять с оглядкой и прогонять `npm test`.

## Карта земель `/map` по блокам-глашатаям

> Перенесено из `docs/history.md` (бюджет летописи исчерпан).

- **Источник точек — блок-глашатай**, а не координаты из заявки: позицию
  блока пишет сервер, а в заявках смешаны координаты от спавна и абсолютные,
  есть заглушки (0, 0). Координаты на карте — от точки появления, как в игре.
- **Хутора тоже на карте** (`HAMLET`): на сайте их не регистрируют, но глашатая
  в игре ставят. У хутора нет страницы, курса и числа жителей — только название
  с глашатая и хозяин (`placedBy`).
- **Данных пока нет:** бэкенд отдаёт `notifier_position` только для одного
  поселения, и ни у кого глашатай ещё не стоит. `WorldMapApiService` возвращает
  пример (7 поселений и 2 хутора, выдуманы) с флагом `demo`: страница предупреждает,
  карточка не ведёт на несуществующие страницы, `/map` под `noindex`.
  Нужен список (например `GET /v1/settlements/map`: id, settlement_id, name, type,
  diplomacy, members_count, placed_by, notifier_position от спавна) — меняется только `load()`.
- **Вид — старинная гравированная карта:** лист бумаги с пятнами и потемневшими
  краями, двойная рамка с градусной разметкой по шагу сетки, волосяная сетка X/Z
  и румбы тушью, роза ветров вокруг Очага, картуш с масштабом. Знаки тушью по типу
  (хутор — кружок с точкой … провинция — замок с флагом), курс — акварельная заливка
  под знаком. Крупные поселения подписаны разрядкой прописными, хутора — мельче.
  Киноварь — только Очаг, север и выбранное поселение. Цвета — токены `--lh-map-*`.
- **Управление:** перетаскивание, Ctrl + колёсико (без Ctrl колёсико листает
  страницу и показывает подсказку), щипок, кнопки, клавиши. Подпись пробует место
  справа, потом слева, не заходит на чужие знаки, кнопки, картуш и за рамку;
  не влезла — скрыта до наведения.
- Под картой — строка условных знаков (подпись к карте) и указатель поселений
  плиткой по удалённости от Очага. Ссылки: кнопка на `/settlements`, «Сообщество», подвал.

**Живые данные.** `WorldMapApiService.load()` делает два параллельных запроса:
`GET /settlements/notifiers` (позиции всех стоящих глашатаев, vsservice PR #144) и `GET /settlements`
(название, тип, курс, жители). Глашатай без поселения в списке (поселение удалено, блок остался)
и гильдии отбрасываются. Пока глашатаев нет (на 28.10.2026 список пуст), показывается пример
с флагом `demo`. `/map` рендерится на сервере по запросу: при пререндере данные замерзали
на момент сборки; запросы при этом идут с сервера и в Network браузера при прямом открытии не видны.

# PROJECT_MAP.md — Last Hearth Landing

## 1. Общее

- Фреймворк: Angular 20 (standalone components, signals).
- Сборщик: `@angular/build:application` (Vite-based).
- Стили: LESS + Tailwind CSS v4.
- UI Kit: Taiga UI 4.x.
- i18n: кастомный сервис `@core/i18n` с pipe `translate`.
- Архитектура: миграция на FSD (Feature-Sliced Design).

## 2. Слои FSD

```text
src/app/
├── app.config.ts / app.component.* / app.routes.ts
├── pages/        — страницы, lazy-loaded
├── widgets/      — композиционные блоки
├── features/     — бизнес-фичи
├── entities/     — бизнес-сущности
└── shared/       — переиспользуемый код
```

## 3. Недавние крупные изменения

### 3.-23 Карта земель `/map` по блокам-глашатаям (пока на примере)

- **Источник точек — блок-глашатай**, а не координаты из заявки: позицию
  блока пишет сервер, а в заявках смешаны координаты от спавна и абсолютные,
  есть заглушки (0, 0). Координаты на карте — от точки появления, как в игре.
- **Хутора тоже на карте** (`HAMLET`): на сайте их не регистрируют, но глашатая
  в игре ставят. У хутора нет страницы, курса и числа жителей — только название
  с глашатая и хозяин (`placedBy`).
- **Данных пока нет:** бэкенд отдаёт `notifier_position` только для одного
  поселения, и ни у кого глашатай ещё не стоит. `WorldMapApiService` возвращает
  пример (7 поселений и 2 хутора, выдуманы) с флагом `demo`: страница предупреждает,
  карточка не ведёт на несуществующие страницы, `/map` под `noindex`.
  Нужен список (например `GET /v1/settlements/map`: id, settlement_id, name, type,
  diplomacy, members_count, placed_by, notifier_position от спавна) — меняется только `load()`.
- **Вид — старинная гравированная карта:** лист бумаги с пятнами и потемневшими
  краями, двойная рамка с градусной разметкой по шагу сетки, волосяная сетка X/Z
  и румбы тушью, роза ветров вокруг Очага, картуш с масштабом. Знаки тушью по типу
  (хутор — кружок с точкой … провинция — замок с флагом), курс — акварельная заливка
  под знаком. Крупные поселения подписаны разрядкой прописными, хутора — мельче.
  Киноварь — только Очаг, север и выбранное поселение. Цвета — токены `--lh-map-*`.
- **Управление:** перетаскивание, Ctrl + колёсико (без Ctrl колёсико листает
  страницу и показывает подсказку), щипок, кнопки, клавиши. Подпись пробует место
  справа, потом слева, не заходит на чужие знаки, кнопки, картуш и за рамку;
  не влезла — скрыта до наведения.
- Под картой — строка условных знаков (подпись к карте) и указатель поселений
  плиткой по удалённости от Очага. Ссылки: кнопка на `/settlements`, «Сообщество», подвал.

### 3.-22 Шрифты: база 15px вместо таиговских 13px, пол для мелкого текста

- **Причина «очень мелко».** Taiga задаёт `tui-root` шрифт `--tui-font-text-s`
  (13px). Всё, что не задаёт размер само — `lh-cta`, меню, подвал, абзацы, —
  наследовало 13px, а узкий шрифт сайта на 13px читается как 11–12px обычного.
- **База — 15px** (`html body tui-root` в `styles.css`, селектор длиннее
  таиговского, иначе стили компонента его перебивают). Кнопки `lh-cta` — 15px,
  меню `nav-button` — 14px явно.
- **Пол для явных размеров:** все `font-size` в стилях компонентов подняты на
  ступень — 10–11px → 12px, 12px → 13px, 13px → 14px. Мельче 13px остались
  только капсовые бейджи (скидка, раздел и минуты на обложке вики) — 12px.
- **Меню на средних экранах:** 768–1199px — 13px и меньше поля, 768–1023px —
  без иконок у подписанных пунктов; девять пунктов иначе не влезали в строку.
- Проверка — обход страниц Playwright с поиском видимого текста мельче 13px.

### 3.-21 Сайт — один контейнер Node (после 502 при первой выкладке SSR)

- **Что случилось.** SSR выкатили схемой из двух контейнеров: `app` (Node) и `web`
  (nginx, проксирует на `app:4000`). Dokploy собирает Dockerfile без compose —
  получилась только последняя стадия, nginx; хоста `app` нет, nginx не стартует,
  сайт отдавал 502 на всё.
- **Решение.** Последняя (собираемая по умолчанию) стадия Dockerfile — Node на
  8080: отдаёт статику, предрендер и серверный рендер сам. `compose.yaml` — снова
  один сервис `web` на `4200:8080`, как до SSR. Стадия `web` с nginx оставлена,
  но по умолчанию не собирается.
- **Сжатие без nginx.** Текстовая статика сжимается при сборке образа
  (`scripts/precompress.mjs`, рядом `*.gz`), `src/server.ts` отдаёт копию по
  `Accept-Encoding`. HTML страниц сжимается на лету (gzip 6): главная 289 → 58 КБ.
- **Правила адресов — в `server.ts`**: `/home` → `/`, без завершающего слэша,
  `/index.html` → `/`, прочие `*.html` — 404 (дубли «чистых» адресов предрендера).

### 3.-20 Моды сервера: список в админке, данные с ModDB, «Скачать всё»

- **Список модов — в админке, а не в коде.** Раньше моды лежали константой
  `SERVER_MODS`, и любая правка требовала выкладки сайта. Теперь их ведут во
  вкладке «Моды» админки (scope `news:create`, как новости и события), а хранит
  бэкенд — vsservice `tasks/006-server-mods.md`, API `/v1/mods*`.
- **Данные о модах берёт бэкенд с ModDB.** Модератор вставляет ссылку — название,
  автор, логотип, версии, файлы и «где работает» приходят сами. Из браузера ModDB
  не спросить: ни у API, ни у CDN файлов нет CORS. По той же причине архив
  «Скачать всё» собирает бэкенд, а не браузер (JSZip упёрся бы в CORS CDN).
- **Совместимость считается на фронте** от `environment.gameVersion`: ModDB отдаёт у
  версии мода список версий игры. Точное совпадение — «подходит», та же ветка
  (1.22.x) — «для 1.22.x», иначе предупреждение. При добавлении по умолчанию
  выбирается самая новая подходящая версия, а не просто самая новая.
- **`/mods` рендерится на сервере по запросу**, а не пререндерится: список меняется
  без выкладки, а предсборка запекла бы список на момент сборки.
- **Серверные моды по умолчанию скрыты** (аудитория `HIDDEN`): игроку они не нужны
  и в архив не попадают.

### 3.-19 SEO: серверный рендер, коды ответа, канонические адреса

> Поисковик (в первую очередь Яндекс) почти не исполняет JS, а динамические
> страницы — статьи вики, новости, поселения, игроки — отдавались пустой
> оболочкой. Плюс любой несуществующий адрес отвечал 200, а главная жила на
> `/home`, хотя сильнее ранжируется корень домена.

- **Рендер на сервере вместо статики.** Сборка переведена на `outputMode: "server"`
  (`src/server.ts`, express + `AngularNodeAppEngine`), режимы задаёт
  `src/app/app.routes.server.ts`: разделы собираются заранее, четыре динамические
  страницы рисуются по запросу, всё под авторизацией остаётся браузеру.
  `routes.txt` удалён — список пререндера читают `gen-project-map.mjs` и
  `gen-sitemap.mjs` из того же файла, чтобы не было второго источника правды.
- **Данные грузятся и на сервере.** Список вики, статья и профиль игрока больше
  не ждут браузера: `isPlatformBrowser` перестал быть гейтом загрузки. Серверный
  HTTP ограничен тремя секундами (`serverApiTimeoutInterceptor`) — медленный API
  отдаёт страницу со скелетоном и кодом 200, данные догружает браузер;
  `authInterceptor` на сервере ничего не делает, поэтому токен в SSR не попадает.
  Ответы API переносятся в браузер трансфер-кэшем, кроме `/serverinfo` и `/discord`.
- **Коды ответа.** `ServerResponseService` пишет статус в `RESPONSE_INIT`:
  несуществующая статья, несуществующий игрок и любой неизвестный адрес отвечают 404. Известный пробел: `/news/<нет>` и `/settlements/<нет>` пока отдают 200 со
  скелетоном — их состояние «не найдено» приходит уже после первой проверки
  стабильности, лечится резолверами или `PendingTasks`.
- **Главная — корень домена.** Роут `''` стал главной, `/home` уводит на `/`
  (301 и в node, и в nginx), `/<путь>/` схлопывается в `/<путь>`; `redirectUri`
  в обоих окружениях и `seo-data` переехали на корень. В Logto нужно добавить
  `https://lasthearth.ru/` (старый `/home/` оставить на две недели).
- **Теги без мусора.** `robots` ставится всегда (`index, follow, max-image-preview:large`),
  ключевые слова убраны из `ISeoData` и всех страниц, canonical появляется только
  со своим адресом (у 404 его нет), `og:image` есть у каждой страницы.
- **Sitemap — часть сборки.** `prebuild` собирает разделы, статьи, новости,
  поселения и игроков (от 10 часов в игре); при недоступном API остаётся прежний
  файл и предупреждение. Изменившиеся адреса уезжают в `dist/indexnow-urls.json`,
  а после выкладки их отправляет `npm run indexnow` (проверено на подменённом
  адресе через `INDEXNOW_ENDPOINT`).
- **Шрифты и иконки.** Google Fonts заменены на свои `@fontsource` (Advent Pro
  Variable, Alegreya, Almendra и Manrope — последний был нужен компонентам Taiga);
  добавлены favicon 16/32/48, `site.webmanifest`, иконки 192/512; `translate="no"`
  и `meta keywords` из `index.html` убраны, мета-подтверждения поисковиков лежат
  закомментированными до значений владельца (задача 010).
- **Подвал — карта сайта для робота.** Выпадающее меню «Сообщество» рендерится
  только по клику, поэтому в подвале появился блок из 12 ссылок на все публичные
  разделы.
- **Деплой.** Один Dockerfile с двумя target: `app` (node:22-alpine, `server.mjs`,
  порт 4000) и `web` (nginx отдаёт статику сам и проксирует HTML, кэш 60 с для
  гостевых страниц, `/profile` мимо кэша). Проверено `docker compose config` и
  curl к node-серверу; `nginx -t` и Lighthouse остались непроверенными (демон
  Docker не запущен, браузера для замеров нет).

### 3.-19 Игроки: «О себе» в профиле и страница `/players`

> Два экрана одной задачи: блок «О себе» на `/player/<ник>` с правкой владельцем
> и модерацией, и список игроков `/players` с поиском, фильтром «был в игре»,
> сортировкой и страницами. Бэкенд — vsservice tasks/005.

- **Адрес — единственный источник истины.** Состояние списка живёт в
  `?q=&seen=&sort=&page=`, значения по умолчанию в адрес не пишутся. Набор текста
  в поиске заменяет запись истории (иначе каждая пауза в наборе плодит запись),
  а фильтр, сортировка и страница пишут новую — «Назад» возвращает прошлый набор
  целиком, а ссылкой на подборку можно поделиться.
- **Длина описания считается в рунах** (`Array.from`), как на сервере: эмодзи
  занимает две UTF-16-единицы, но один символ, и счётчик «N / 500» разошёлся бы
  с серверным лимитом. Строки считаются по `\r\n?` — Windows-переносы тоже.
- **Сохранение не перезагружает страницу.** Компонент «О себе» эмитит новый
  текст, страница держит его в сигнале-оверрайде и отдаёт в блок; профиль с
  сервера не перезапрашивается.
- **Пагинация — общий компонент** `shared/ui/pagination` и чистая функция
  `buildPaginationPages`: короткий список показывается целиком, длинный —
  «1 … 4 5 6 … 12». На экране уже 480px остаются стрелки и «X из Y».
- **Поселение и роль считаются один раз на список.** Общая карта
  «игрок → поселение и роль» вынесена в `entities/settlement/lib`
  (`buildSettlementMembers`) и используется и профилем, и страницей игроков:
  раньше профиль искал поселение перебором всех поселений на каждого игрока.
- **Словарь пагинации — отдельный домен** `pagination`, зарегистрирован
  глобально: компонент общий, а на страницу игроков приезжает только
  `PLAYERS_I18N`. В сам `players` добавлены ключи статуса и роли карточки
  (`status.*`, `role.*`) — в списке ключей ТЗ их не было, но карточке они нужны.
- **Кнопка внутри блока меньше полноразмерной CTA** (`0.625rem 1.125rem` —
  как в карточках LFG и редакторе оформления): кнопка «Написать о себе» в размере
  главной кнопки страницы выглядела слишком высокой для действия внутри панели.
- **Сортировка — проектный выпадающий список** `lh-input type="select"` (тот же
  контрол, что в формах поселений и админке): нативный `<select>` выбивался из
  системы — свои цвета из ОС, свой вид списка. Подпись поиска при этом скрыта для
  скринридера: у поля поиска она нужна только ему, а не глазам.
- **Высота поля контрола — переменной** `--lh-input-min-height`: `lh-input`
  держит 50px по умолчанию, а сортировка на игроках стоит в одном ряду с полем
  поиска (2.75rem) и была выше соседа. Общий контрол не меняли — переопределена
  только его высота в этом месте, формы поселений и админки остались на 50px.
- **Кнопка «Повторить» в состоянии ошибки — размера `m` Taiga** (2.75rem вместо
  3.5rem по умолчанию). Правка сделана в общем `shared/ui/error-state`, поэтому
  кнопка уменьшилась во всех состояниях ошибки, а не только на странице игроков:
  размер `l` был выше любого элемента вокруг неё.
- **Найдено проверкой «ключи шаблонов против словаря»:** 25 ключей прошлых задач
  (`wiki.mine.*`, `wiki.public.loading`, `wiki.review.showSince`,
  `wiki.editor.conflict.*`, `profile.nav.wiki`) в словарях отсутствуют —
  страницы показывают сами ключи. Паритет ru/en этого не видит: он сравнивает
  словари между собой, а не с шаблонами. Не исправлено в этой задаче (чужой
  домен), ключи этой задачи проверены все.

### 3.-18 Преалодинг разделов меню и прогрев кэша магазина

> Клик по пункту меню ничего не показывал, пока браузер скачивал чанк страницы и
> её словарь: паузу приходилось прикрывать полосой загрузки
> (`RouteLoadingService`). Магазин добавлял второе ожидание — пререндер кладёт в
> HTML `/market` только разметку, товаров в `ng-state` нет (1,7 КБ состояния),
> поэтому сетка рисовала скелетон до ответа `/donate/shop/items`.

- **Преалодинг чанков.** `routes/nav-preloading.strategy.ts` +
  `withPreloading(NavPreloadingStrategy)` в `core/config/app.config.ts`: роутер
  сам скачивает страницы из `routes/nav-preload-paths.constant.ts` (home, rules,
  wiki, settlements, events, market) в окне простоя после первого `NavigationEnd`.
  Список явный, а не `PreloadAllModules`: полный преалодинг тянул бы ещё админку
  (208 КБ), профиль и юридические словари (`legal-i18n` 109 КБ) — в сборке 89
  ленивых чанков. Роуты со стражами и с параметрами (`player/:nick`, `news/:id`)
  не берутся; на сервере стратегия молчит (`isPlatformBrowser`).
- **Цена вопроса.** Тяжелее всех `/rules`: `rules-component` 178,7 КБ raw
  (20,7 КБ передачи) + `rules-i18n` 318,1 КБ (35,8 КБ). Остальные пять разделов —
  порядка 10–15 КБ передачи каждый, `market-component` 52,8 КБ raw (8,8 КБ).
- **Прогрев кэша магазина.** `core/services/shop-prefetch.service.ts` стартует из
  `LayoutComponent` через `afterNextRender` и вызывает
  `DonateService.prefetchShopItems$()`: тот же общий поток, но с
  `SKIP_ERROR_ALERT` — иначе алерт «Нет соединения с сервером» всплывал бы на
  странице, где магазин никто не открывал. Повторный вызов `start()` игнорируется,
  а флаг `shopItemsRequested` не даёт второму запросу уйти, если магазин уже открыт.
- **Грабли кэша.** `shareReplay(1)` запоминал и неудачу: `errorInterceptor`
  подменяет ошибку GET на `EMPTY`, поэтому `catchError(() => of([]))` в сервисе не
  срабатывал, поток завершался без значения, а `titles`/`kits`/`special` подписаны
  только на `next` — скелетон оставался навсегда. Кэш собран через
  `share({ connector: () => new ReplaySubject(1), resetOnError: true, resetOnComplete: false, resetOnRefCountZero: false })`:
  успех живёт всю сессию, ошибка кэш сбрасывает, и следующий подписчик делает новый
  запрос. Обычный (не тихий) путь поведения не изменил.
- **Ожидание простоя.** `shared/lib/when-idle.function.ts` — `requestIdleCallback`
  с запасным `window.setTimeout` (Safari получил `requestIdleCallback` только в 18).
- Проверено: `npm run verify` зелёный; `ng build` проходит, 11 пререндер-роутов,
  начальный бандл 1,37 МБ raw / 287 КБ передачи при бюджете 1,4/1,8 МБ.

### 3.-17 Загрузка картинок вики с `UPLOAD_PURPOSE_WIKI`

> Обложку и картинки статьи вики нельзя было загрузить: бэкенд отклонял
> запрос, потому что вики пользовалась назначением новостей
> (`UPLOAD_PURPOSE_NEWS`), а для вики заведено своё — `UPLOAD_PURPOSE_WIKI`.

- **Что исправлено:** назначение `UPLOAD_PURPOSE_WIKI` добавлено в
  `UploadPurpose` (`entities/media/model/media.types.ts`) и в контракт
  (`API_CONTRACT.md` §2.15); `uploadImage` в `wiki-editor-page.component.ts`
  грузит с ним и обложку, и картинки текста (ввод разметки получает ту же
  функцию).
- **Связь с 3.-11:** там `UPLOAD_PURPOSE_WIKI` числился в «не сделано» —
  теперь закрыт.

### 3.-16 Грабли: компонент без `styleUrl`

> Кнопка «Редактировать» на странице статьи не уменьшалась, хотя правки в
> `wiki-article-page.component.less` были на месте. Причина — **декоратор
> компонента не подключал файл стилей**: `styleUrl` в нём просто отсутствовал,
> поэтому LESS лежал на диске и в сборке не участвовал.

- **Как выглядело.** Правки отступов и размеров «не работали» без единой ошибки
  сборки: Angular не считает файл стилей обязательным, а лишний `.less` рядом с
  компонентом никого не смущает.
- **Что исправлено:** `styleUrl: './wiki-article-page.component.less'`. Стили
  ленивых компонентов попадают в JS-чанк, поэтому искать их в `dist/**/*.css`
  бесполезно — проверять надо чанк.
- **Профилактика:** прошёл скриптом по всем компонентам wiki, админки и
  `entities/wiki`: нет ни одного файла стилей, который лежит рядом и не
  подключается, и ни одной ссылки `styleUrl` на несуществующий файл.
- **Урок:** «стиль не применился» без ошибок сборки — сначала проверить, что
  декоратор вообще знает про этот файл.

### 3.-15 Правки по замечаниям: размеры, подписи, экран проверки

> Пользователь прошёл вики руками и вернул список. Ни одна правка не потребовала
> бэкенда — всё закрылось фронтом.

- **Иконки.** У `tui-icon` в проекте нет базового размера, поэтому иконка без
  класса рисуется в свой квадрат и рядом с мелким текстом выглядит огромной.
  Часы на карточке не имели ни класса `size-*`, ни размеров в стилях; у
  «чипов» статьи был задан только `font-size` без ширины и высоты, чего мало.
  Теперь и там, и там заданы `width`/`height`/`font-size`, а иконки в кнопках
  получили `size-4!` — как в остальных шапках страниц.
- **Подписи автора.** Сервер хранит в статье subject из токена, поэтому в
  «Последняя правка — …» стоял идентификатор вида `qh6u7ut3b6y6`. Добавлен
  `WikiAuthorNameService` в `entities/wiki`: он переводит идентификатор в
  игровое имя через существующий `GET /users:batchGet` и запоминает результат,
  чтобы одна и та же подпись не запрашивалась на каждой странице.
- **Высоты и отступы.** Кнопка «Новая статья» в панели вики была выше соседних
  (свой отступ из `styles.css`); «Предложить правку» на странице статьи была
  кнопкой во всю ширину ряда; ряд кнопок лип к статье. Всё приведено к
  компактному размеру, у ряда появился отступ.
- **Лоадер.** Редактор открывают по прямой ссылке, и до ответа сервера форма
  выглядела пустой. Добавлено состояние `loadingArticle` и полоса загрузки с
  `common.loading`; анимация уважает `prefers-reduced-motion`.
- **Уход со страницы.** Кнопка «назад» полагалась на страж маршрута: он
  спрашивает подтверждение и только потом пускает, из-за чего первый клик
  выглядел как «ничего не произошло». Теперь кнопка ведёт навигацию сама — один
  клик даёт один исход: либо уходим, либо получаем окно, после которого точно
  уходим.
- **Экран проверки (главное).** Очередь показывала только заголовок. Теперь
  предложение раскрывается: **полная статья, как её написал игрок** (через тот
  же `WikiArticleViewComponent`, что и публичную страницу), **построчное
  сравнение** с опубликованным текстом через уже имеющийся `lineDiff`, счётчик
  добавленных и удалённых строк, переключатель «только изменения / весь текст» и
  решения прямо оттуда. Отдельный эндпоинт не понадобился: `ListSuggestions`
  уже отдаёт предложение целиком, а текущая статья приходит из `GetArticle`.
- **Сравнение по полям.** Построчного сравнения текста мало: предложение может
  менять заголовок, раздел, теги, обложку или «См. также», и по тексту этого не
  видно. Добавлен `compareWikiArticles`: он сравнивает опубликованную статью с
  предложенной и отдаёт **только различия** («было → стало»), длинные значения
  показывает построчно. Текст статьи из этого списка исключён — он сравнивается
  отдельно и построчно, дублировать его в таблице незачем.
- **Правка показывается только изменениями.** Сначала в раскрытом предложении
  всегда рисовалась полная статья игрока — и для правки это оказалось лишним:
  редактор читал весь текст там, где изменилась одна строка. Теперь ветки
  разошлись: **предложение правки** показывает таблицу «было → стало» по полям и
  построчное сравнение, а **предложение новой статьи** (сравнивать не с чем)
  показывается целиком. Переключатель «весь текст / только изменения» убран — он
  существовал ради того самого полного текста.
- **Проверено:** `npm run verify` — всё зелёное (локали 423/423, FSD, контраст,
  типы); `ng build --configuration production` — успешно, 11 пререндер-роутов,
  бандл 1.36 MB. Браузером не проверялось.

### 3.-14 Грабли: браузерный код в SSR

> После подвязки вики на API `ng build` падал с
> `ReferenceError: cancelAnimationFrame is not defined` — и это ломало
> пререндер всего сайта, а не только вики.

- **Причина.** В `wiki-editor-page` анимационные кадры отменялись в
  `destroyRef.onDestroy` **без проверки платформы**. На сервере этого
  обработчика никто не ждёт до момента завершения рендера — но при завершении
  SSR Angular уничтожает приложение, и обработчик вызывается. А
  `cancelAnimationFrame` в Node нет: там есть `setTimeout`, но не кадры.
- **Что исправлено:** и отмена кадра в `onDestroy`, и планирование кадра в
  синхронной прокрутке теперь под `isBrowser`. У `wiki-markup-input`
  проверка уже была — он единственный компонент вики, который её имел.
- **Вывод для будущих компонентов.** `afterNextRender` на сервере не
  выполняется, поэтому работа с `window`, `document` и кадрами внутри него
  безопасна. А вот `constructor` и `onDestroy` выполняются **на обеих
  платформах**: всё браузерное там обязано быть под `isPlatformBrowser`.
- **Проверено:** `ng build --configuration production` — успешно,
  `Prerendered 11 static routes`. До правки сборка падала на пререндере.
  В production-сборке нет ни `NG0751`, ни сообщений OIDC про `Storage was
undefined`: `NG0751` относится к `ng serve` с HMR (единственный
  `@defer` живёт в `layout.component.html` и к вики отношения не имеет),
  а OIDC-сообщения — отладочные и серверные.

### 3.-13 Фронт вики на API и модерация предложений

> Продолжение 3.-11 и 3.-12. Вики перестала быть локальной: статьи приезжают
> с сервера, а игроки предлагают правки через проверку.

- **`entities/wiki`** — новый слайс по конвенциям новостей: DTO повторяют
  контракт `wiki.v1` (snake_case, энумы строками вида
  `ARTICLE_STATUS_PUBLISHED`), UI-модель в camelCase, мапперы и API-сервис.
  Энумы приходят строками, а не числами: grpc-gateway сериализует их именами.
- **`WikiStoreService` переписан с localStorage на HTTP**, но сохранил
  **синхронный** интерфейс: компоненты читают снимок из сигналов, а запись
  уезжает на сервер. Так список, просмотр и редактор не пришлось переписывать
  на потоки. Автосохранение осталось в браузере — это несохранённая форма.
- **Версия правки.** `save` отправляет `expected_version` — ту, что редактор
  открыл. Сервер отказывает, если статью успел изменить кто-то другой, вместо
  тихой перезаписи. Раньше это было неактуально: в localStorage конкурентов нет.
- **Модерация.** `WikiSuggestionsComponent` — вкладка «Предложения» в панели
  вики: фильтры со счётчиками, карточки, одобрение и отклонение с обязательной
  причиной. Редактор научился режиму `?suggest=1`: игрок видит «Отправить на
  проверку» вместо «Опубликовать», и прямых операций записи ему не показывают.
- **Доступ.** Маршрут `wiki/edit/:id` переведён с `adminGuard` на `userGuard`:
  игрок приходит в тот же редактор, чтобы предложить статью. Что ему разрешено
  записать, решает сервер по scope — интерфейс лишь не показывает лишних кнопок.
- **Плашка о локальном хранении удалена** вместе со строкой: она больше не
  соответствует правде.
- **Проверено:** `npm run verify` — все шаги зелёные (FSD 0 новых нарушений,
  локали 411/411, контраст, типы); `ng build --configuration production` —
  успешно, начальный бандл 1.36 MB, 11 пререндер-роутов. Браузером не
  проверялось: в окружении нет Chrome.
- **Вход для игрока (добавлено после проверки).** Первая версия подвязки
  оставила игрока без входа: единственные ссылки в редактор жили в панели
  админки (`/profile/admin`, под `adminGuard`), а на `/wiki` кнопки не было
  вовсе — то есть предложить статью обычный игрок не мог никак. На странице вики
  появилась кнопка: редактору — «Новая статья», игроку — «Предложить статью»
  (`/wiki/edit/new?suggest=1`), гостю — «Войдите, чтобы предложить статью».
  Режим предложения читается один раз при открытии редактора и переживает любые
  переписывания адреса внутри него (заготовка, сохранение, дублирование).
- **Не сделано:** экран «Мои предложения» со статусами в профиле, уведомление
  автора о решении, `UPLOAD_PURPOSE_WIKI` (картинки пока грузятся с
  назначением новостей).

### 3.-10 Восстановление сессии при возврате на сайт

> Жалоба: «при входе на сайт сессия не сохраняется, приходится снова нажимать
> «Войти»». Причина не в хранилище, а в проверке входа.

- `OidcSecurityService.checkAuth()` только читает токены из `localStorage` и не
  продлевает их. Logto выдаёт access- и id-токен на час, refresh-токен — на
  14 дней. Через час после входа `checkAuth()` возвращал
  `isAuthenticated: false`, действующий refresh-токен никто не использовал, и
  шапка показывала «Войти». Продление работало только внутри открытой вкладки:
  `startTokenValidationPeriodically` запускается, лишь когда `checkAuth()` уже
  признал токены действительными.

### 3.-5 Управление поселением: роли, заявки, владение, контакты, админка

> Ветка `feat/settlement-management` = `main` + влитая `feat/settlement-roles-ownership`.
> Главная жалоба была не в отсутствии функций, а в попапах: страница поселения
> дёргала owner-only эндпоинты у обычного жителя, и на каждый 403/404
> `errorInterceptor` показывал алерт.

**Почему попапы нельзя было убрать одним `catchError`.** `errorInterceptor`
(`core/interceptors/error.interceptor.ts`) для GET-запросов сам открывает алерт и
возвращает `EMPTY` — к моменту, когда ошибка доходит до компонента, алерт уже
показан. Лечится двумя слоями, и одного мало:

1. `new HttpContext().set(SKIP_ERROR_ALERT, true)` на все GET-ы, доступные не
   всем: `getSentInvitations`, `getJoinRequests$`, `getMyJoinRequests$`,
   `getRequestSettlementStatus$`, `getSettlementInfo`. Для этого у методов
   появился опциональный параметр `context?: HttpContext`.
2. Гейт по праву **перед подпиской**: стрим не запускается, если права нет. Без
   первого слоя гонка при смене владельца всё равно дала бы 403; без второго
   запрос уходил бы зря.

**Аудит вспомогательных GET (следующий этап той же борьбы с попапами).**
Цель: у рядового пользователя не остаётся алертов на фоновых GET-ах, чьи
потребители и так деградируют молча. Правило прежнее: `catchError` в
компоненте не спасает — алерт ставит `errorInterceptor`, поэтому на запрос
вешается `new HttpContext().set(SKIP_ERROR_ALERT, true)`, а у потребителя
проверяется/добавляется catchError, иначе ошибка уйдёт в unhandled.

Покрытые запросы (все с SKIP, потребители ловят ошибку):

- `entities/donate` — `getMyBalance$`, `getMyPurchases$`.
- `entities/referral` — `getMyCode$`, `getMyStats$` (виджет → null/нули).
- `entities/user` — приватный `leaderboardStats$` (топ-200 для тултипов
  player-chip; внутри `getPlayerStats$` уже был catchError → null).
- `entities/settlement-tag` — `getTags$`; в `SettlementTagStore.loadTags$`
  добавлен `catchError(() => of([]))`, без него ошибка летела бы в
  конструктор `settlements.component`.
- `entities/settlement` — `getSettlements` (страница селений и главная
  имеют свои error-состояния, админ-панель ловит в catchError).
- `entities/news` — `getList` (главная ловит → пустой список).
- `entities/discord` — `getMessages$`, `getImages$` (дипломатия/галерея/чат
  имеют собственные error-сигналы; раньше был двойной фидбек: алерт + свой
  стейт). В `game-chat` `watchChat$` catchError внутри `switchMap`, чтобы
  один сбой опроса не убивал polling-поток.
- `core/services/server-information.service` — `getOnlinePlayersCount$`,
  `getTime$`, `getLeaderBoard`, `getPlayerStats$` (шапка → null/прочерк,
  статистика → пустая таблица, профиль → null).

Намеренно оставлены с алертом: админские поверхности (hunger-games,
верификации), `searchUser$` (поиск без результата-ошибки должен сообщать),
POST/PUT/DELETE (фидбек через `RequestStatusService`).

**API-слой (`entities/settlement/api/settlement.service.ts`)** приведён к живой

### 3.-3 Карточка селения, тултип жителя и цвет тегов

### 3.10 Карточка вики, редакция 2: читальня у очага

- Заменяет анатомию §3.9: оправа с паспарту, сургучная печать, бирка раздела на
  раме и чернильная линейка убраны — карточка стала тише, подпись несёт один свет.
- Концепт: список вики — читальня у очага (имя сервера Last Hearth даёт метафору).
  Сигнатура: тёплое пятно света следует за курсором (`__glow`, только `transform`
  и `opacity`, отставание на `--lh-ease-smooth`); на таче и при уменьшенном
  движении свет выключен (`pointerType !== 'mouse'`, `prefers-reduced-motion`).
- Композиция: первый лист порядка — разворот (`--lead`, `grid-column: 1 / -1`):
  пластина 52% слева, текст справа, заголовок 2.25rem, теги статьи под вступлением
  (`WikiCard.tags`, не более трёх); на <40rem разворот складывается в колонку.
- Рядовой лист: пластина в край карточки с двойным затемнением (верхнее — под
  капитель `__hud`, нижнее — под заголовок); заголовок стоит на пластине цветом
  `--lh-parchment-3`. Без обложки пластина — ночной градиент, заголовок читаем всегда.
- Черновик переехал из пластины в колофон: на узкой пластине он теснил бирку
  раздела и минуты (`__hud` получил `flex-wrap`, минуты — `nowrap`).
- Узкие экраны: дорожка `minmax(min(17rem, 100%), 1fr)`, `min-width: 0` у карточки;

  Правка по замечанию с телефона: рядом стояли пилюля, прямоугольник 0.7rem и 1.5rem.
- Концентричность углов пластины задана явно, а не обрезкой карточки: радиус

  рядового листа и сложенного разворота, лев у разворота), остальные углы — прямой
  стык. Формула из DESIGN_SYSTEM §6.3.2 при нулевом зазоре: r внутренний = r панели.
- Угол карточки острее панелей страницы: `--lh-panel-radius: 0.75rem` переопределён
  на `.wiki-card` (правка по продакшен-кадру: 1.5rem читался слишком круглым).
  Пластина наследует ту же переменную, концентричность не ломается.

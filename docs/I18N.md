# i18n

> **Что это.** Как устроены переводы и как править текст, **не читая словарь целиком**.
> Самый большой словарь — `rules.i18n.ts` (222 kB, 776 ключей, ~76k токенов при чтении).

## Устройство

- Словари: `src/app/core/i18n/translations/features/<домен>.i18n.ts`, ключ верхнего уровня = домен (`rules`, `faq`…), внутри `ru` и `en`.
- Реестр: `src/app/core/i18n/translations/index.ts` (общие домены: common, header, footer, shared, news) + `registry.ts`
  (`TRANSLATIONS` + `registerTranslations`, слияние поверхностное — домены не пересекаются).
- Страничные домены грузятся вместе с роутом: `loadPage(() => import(component), [() => import(dict)])` в `app.routes.ts`.
- Пайп `translate`; сервис `@core/i18n`.

## Правила

1. Любой новый текст — **сразу в обе локали** (`ru` и `en`). Паритет проверяет `npm run i18n -- check`.
2. Словарь должен подгружаться на том роуте, где используется. Классическая ловушка: `/profile/admin`
   не грузит словарь поселений — если добавляете туда текст из `settlements.i18n.ts`, добавьте словарь в `loadPage` этого роута.
3. Ключи не переименовывать без правки шаблонов: ключ ищется по всему коду.

## Точечная правка без чтения файла

```bash
npm run i18n -- find "войти в поселение"     # где это лежит: словарь + путь ключа
npm run i18n -- get rules rules.title        # текущее значение в ru и en
npm run i18n -- set rules rules.title "Новый заголовок"                # обе локали
npm run i18n -- set faq faq.questions.offer "..." --lang ru            # только ru
npm run i18n -- stats                        # размеры, число ключей, расхождения ru/en
npm run i18n -- check                        # паритет локалей; код возврата 1 при расхождении
```

- `<файл>` — домен (`rules`) или путь к `.i18n.ts`.
- `<путь>` — ключи через точку без языка: `rules.title`, `faq.questions.offer`.
- `--print` печатает обновлённый файл в stdout вместо записи — для песочниц, где письмо на диск запрещено.
- Инструмент не создаёт временных файлов: словарь разбирается в процессе.

Legacy: `scripts/check-i18n.mjs <файл>` делает то же, что `i18n-tool check`, но через временный модуль
в `%TEMP%` — в песочницах это может быть запрещено.

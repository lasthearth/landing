# Исследование: что мешает конверсии (срез 25–27.10.2026)

> **Что это.** Разовый снимок, а не постоянный документ: данные Clarity за три дня плюс разбор кода
> пути конверсии. Данные сняты 27.10.2026, задачи — в `docs/TODO.md` § «Продукт»,
> метод снятия — `docs/TOOLING.md` § «Clarity».

## Откуда цифры

Clarity Data Export API через `npm run clarity`, окно 25–27.10.2026, только не-боты и только те
пользователи, которые дали согласие на аналитику (Clarity подключается по сигналу `ConsentService`).
Абсолютные числа поэтому занижены относительно реального трафика; соотношения между страницами применимы.

Два запроса из восьми прошли, остальные вернули 503/500 на стороне Clarity: разбивка по устройствам,
«bounce rate» и выборка записей сессий на момент снятия недоступны. Лимит — 10 запросов на проект в сутки,
исчерпан. Повторить снятие можно на следующий день теми же командами.

## Что это значит

**1. Главная страница не доводит до действия.** 49 секунд и 46 % глубины скролла при 87 сессиях:
половина посетителей не долистывает первый-второй экран. Причины в коде: строка CTA в герое скрыта на
мобильных (`hidden sm:flex`, `src/app/features/home/home.component.html:50`), дубль есть только под
каруселью (:84); первый визит накрыт полноэкранным сплешем с автоплеем `/welcome-video.mp4` (650 КБ)
и блокировкой прокрутки (`src/app/layout/layout.component.ts:133`, `src/app/features/welcome/welcome.component.ts:156`);
после входа герой целиком заменяется (`@if (!isAuthed())`, :3 и :114) — сдвиг примерно на 600 px;
баннер согласия появляется через `@defer (on idle)` и поздно добавляет ~190 px нижнего отступа
(`src/app/app.component.html:20`, `src/styles.css:1891`).

**2. `/market` — самая посещаемая страница и главный источник мёртвых кликов.** 109 мёртвых кликов
на 138 сессий: люди кликают то, что не реагирует. Вероятные источники: вкладки без `aria-selected`
и без обработки стрелок (`src/app/features/market/market.component.html:44`), селекторы срока и цены
в диалоге покупки без признака выбранного состояния (`purchase-dialog.component.html:28`), карточки
наборов. Отдельный тупик: гость видит кнопку «Купить» (баланс не загружен → `missingAmount()` равен 0,
`purchase-dialog.component.ts:141`), POST падает с «Требуется авторизация», а входа в диалоге нет.
Страница при этом пререндерится, поэтому товары и цены доезжают только в браузере (`src/app/app.routes.server.ts:12`).

**3. `/profile/how-play` — страница, куда попадает новичок после регистрации, и с неё массово возвращаются.**
Quickback 0.80 на сессию при 50 сессиях. Механика: `guestGuard` отправляет вошедшего с `/start-game`
на `/profile/how-play` (`src/app/core/guards/guest.guard.ts:25`), а `profile.component.html:273`
подменяет содержимое роутера экраном ожидания, пока заявка не одобрена. Человек приходит за инструкцией
«как установить и зайти» и видит ожидание — уходит назад.

**4. `/settlements` почти всегда заканчивается возвратом.** Quickback 0.95, 19 секунд на сессию:
клик по поселению и немедленный возврат. Страница поселения рендерится на сервере, а участники
догружаются запросом, ошибка которого уходит в `console.error` (`src/app/features/settlements/settlements.component.ts:230`).
Проверить запись сессии в этот момент не удалось: API записей вернул 503.

**5. Ошибок JS в Clarity нет ни на одной странице, и это не здоровье, а слепое пятно.**
`errorInterceptor` превращает ошибку GET в `EMPTY` после одного тоста (`src/app/core/interceptors/error.interceptor.ts:49`),
остальные потоки глушат ошибки через `catchError(of([] | null))` (`home.component.ts:262,272,283,305`,
`user.service.ts:479`, `notification.service.ts:39`). Новость «сервер не ответил» выглядит как
«Новостей пока нет». Пока не сделан план `docs/LOGGING.md`, реальные отказы не видны ни нам, ни Clarity.

**6. Конверсия сейчас не измеряется вовсе.** Номер счётчика Метрики не выдан (`METRIKA_ID = 0`,
`src/app/core/services/analytics.service.ts:16`), а `goal()` молча выбрасывает событие, если счётчик
ещё не загружен (:145): все `cta_start_game` и `sign_up_click`, отправленные до ответа на баннер
согласия, теряются безвозвратно. Семь целей расставлены в коде, но не доходят никуда.

**7. Вход теряет контекст.** `authorize()` ходит по фиксированному `redirectUri`, поэтому после входа
человек всегда оказывается на `/` — ни `/market`, ни `/join/:code` не сохраняются
(`src/app/entities/user/api/user.service.ts:313`). Экрана «войдите, пожалуйста» в приложении нет:
все три гарда молча редиректят на `/` (`user.guard.ts:29`, `admin.guard.ts:31`, `app.routes.ts:428`).
При медленном продлении токена `/profile` ждёт до 15 с (`session-restore-timeout.constant.ts:9`) и
потом всё равно выбрасывает на `/`.

**8. Формы теряют введённое.** Диалог верификации открывается пустым, если GET с вопросами упал
(`player-verification-form.component.html:3`): 8 обязательных полей, черновика нет, кнопка просто
заблокирована без сводки ошибок. В формах поселений `clearSettlementDraft()` вызывается до ответа POST
(`village-form.component.ts:174`, `camp-form.component.ts:157`), а файлы в черновик не попадают вовсе
(`src/app/shared/lib/setup-settlement-draft.function.ts:31`): таймаут 30 с стоит потери текста и 16 изображений.

**9. Отдельный баг данных, не UX.** Все шесть форм поселений отправляют `type: 'CAMP'`
(camp:141, village:158, city:172, guild:140, township:165, region:188), хотя
`create-settlement-from.component.html:7` ведёт пользователя по уровням. Выбранный уровень до сервера не доходит.

**10. Пополнение баланса нельзя отследить.** Перевод ручной, по СБП на номер телефона
(`how-to-buy.component.html:90`), заявка на сервере не создаётся (`donate.service.ts:326` только читает их),
а в комментарий платежа попадает ник или заглушка «Неизвестный» (`how-to-buy.component.ts:70,156`):
платёж может не найтись. Комиссия Boosty +300 ₽ видна только внутри текста диалога (:110).

поэтому инструментацию стоит делать один раз на две задачи.

## Как повторить снятие

```bash
npm run clarity -- dashboard "Sessions, engagement time and scroll depth by page URL for the last 3 days"
npm run clarity -- dashboard "Rage clicks, dead clicks, excessive scrolling, quickback clicks and JavaScript error counts by page URL for the last 3 days"
npm run clarity -- recordings --days 2 --count 15 --dead --url /market   # на 27.10 возвращал 503
```

Формулировки запросов менять не стоит: запросы со словами «bounce rate» и с разбивкой по устройствам
Clarity сейчас отдаёт как 503. Один запрос — одна метрика.
